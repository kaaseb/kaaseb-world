# مقياس دقة الفرن (Furn accuracy scorecard)

`npm run eval` يشغّل **موجّه الـBOQ الحقيقي** على مشاريع حقيقية ويقارن النتيجة بما أكّده المالك أنه الصحيح، ويطبع **نسبة الدقة رقمًا** مع تحديد كل بند خاطئ وسببه.

## كيف تضيف مشروعًا
1. أنشئ مجلدًا `evals/fixtures/<اسم-الحالة>/`.
2. ضع الملفات في `files/` (الـBOQ + المرفقات). هذا المجلد **لا يُرفع إلى Git** (مستندات عملاء).
3. اكتب `expected.json`:
   - `boq` اسم ملف الـBOQ، و`spec` / `drawing` / `other` قوائم أسماء المرفقات.
   - `expect.items[]`: لكل بند صحيح `match` (كلمات لازم تظهر في وصفه)، و`quantity` / `unit` / `thickness_mm` اختياريًا.
   - `expect.absent[]`: كلمات لا يجوز أن تظهر في أي بند مقبول (مثل `terrazzo`).
   - `minItems` / `maxItems`: حدود عدد البنود المقبولة.
   - `confirmed: true` بعد ما يراجعه المالك (الحالات الحالية توقعات المساعد — غير مؤكدة).
4. شغّل `npm run eval -- <اسم-الحالة>`.

## ماذا تحتاج
بيئة التطبيق نفسها (`.env.local` أو بيئة السيرفر): مفاتيح S3 ومزوّد الذكاء. **كل تشغيل يستهلك نداءات ذكاء** بقدر معالجة المشروع في الواجهة — شغّله عن قصد.

## النتائج
كل تشغيل يكتب ملفًا كاملًا في `evals/results/` (لا يُرفع إلى Git) فيه البنود المقبولة والمستبعدة والتغطية — لمراجعة أي فرق.
